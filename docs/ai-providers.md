# AI Providers

MARTY must not depend on one AI provider. Business logic talks to the small
interface in `app/integrations/ai/base.py`; provider adapters translate it to each
provider's API.

## Interface

```python
class LLMProvider(Protocol):
    name: str

    async def complete(self, request: CompletionRequest) -> CompletionResult: ...
```

- `CompletionRequest`: messages (`ChatMessage` with role, content, tool calls),
  optional tool specs (name, description, JSON Schema), temperature and
  output-token limit.
- `CompletionResult`: the assistant message (text and/or tool calls), the provider
  and model that answered, and token usage when reported.

Adapters map failures onto three error types:

| Error | Meaning | Chain behaviour |
| --- | --- | --- |
| `RateLimitedError` | HTTP 429 or quota exhausted | Cooldown (`Retry-After` if given, else 60 s), try the next provider |
| `ProviderUnavailableError` | Timeout, network error, 5xx, unknown model, rejected key | Cooldown (30 s by default; longer for auth errors), try the next provider |
| `InvalidRequestError` | Our request is malformed | Raised immediately: retrying elsewhere would hide a bug |

`FallbackChain` (implemented, `app/integrations/ai/fallback.py`) tries providers in
`AI_PROVIDER_ORDER`, skips those cooling down, and raises
`AllProvidersFailedError` when none answered. The chain is itself an
`LLMProvider`, so the orchestrator does not know whether it talks to one provider
or several.

## Planned adapters (Phase 1)

Groq and Ollama expose OpenAI-compatible chat-completions endpoints, and Google
documents an OpenAI-compatible endpoint for the Gemini API. The plan is one
`OpenAICompatibleProvider` built on `httpx` (no vendor SDK), configured three
ways:

| Provider | Base URL | Notes |
| --- | --- | --- |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` | Initial primary option (free tier) |
| Groq | `https://api.groq.com/openai/v1` | Fallback (free tier) |
| Ollama | `OLLAMA_BASE_URL` + `/v1` | Optional, fully local |

Phase 1 verifies tool calling on each endpoint with real requests. If Gemini's
compatibility layer turns out to be insufficient, a native Gemini adapter
(`generateContent`) is added behind the same interface. Adapter tests use
`httpx.MockTransport` with recorded response shapes.

Model names are configuration (`GEMINI_MODEL`, `GROQ_MODEL`, `OLLAMA_MODEL`), never
hard-coded. Phase 1 adds a script that lists the models available to the configured
keys, so you pick from what the account can actually use.

## Free-tier quotas

Free-tier limits differ per model, change over time and are not unlimited. MARTY
does not encode specific numbers. Instead:

- Rate-limit responses trigger a cooldown and fallback.
- Slash commands, briefings and reports are generated by code and work without an
  LLM.
- One tool-calling loop per message, capped at a few iterations.
- Compact context: profile memories, the top relevant long-term memories, recent
  messages plus the conversation summary, and a short schedule snapshot instead of
  raw tables.
- Token usage is stored per message, so consumption is visible.

## Tool calling

Tools are Python functions with a Pydantic argument model. The registry derives the
JSON Schema sent to the model; the executor validates the model's arguments with
the same Pydantic model before running anything. Invalid arguments are returned to
the model as a tool error, so it can correct itself within the iteration cap. Tool
results are compact JSON. See the policy tiers in
[architecture.md](architecture.md#4-tools-with-policy-tiers-instead-of-free-form-actions).

## What is sent to providers

Sent: the user's message, recent conversation, relevant memories, and the schedule
or progress data a tool returned.

Never sent: credentials, tokens, API keys, database identifiers beyond what tools
need, or descriptions of personal calendar events (MARTY does not store them).

**Data-use terms matter for a personal assistant.** At the time of writing,
Google's Gemini API terms say that content sent to the free (unpaid) tier may be
used to improve Google's products and may be reviewed by humans. Check the current
terms of Gemini and Groq before sending personal data. Ollama is the only option
where nothing leaves the server. On the current development machine (Intel
i7-1255U, integrated graphics, 15 GB RAM) only small models run, slowly on the CPU,
so Ollama is realistic as a last-resort fallback rather than the primary provider.

## Language

Prompts and tool descriptions are written in English. The system prompt instructs
MARTY to always answer the user in natural Spanish (Spain).
